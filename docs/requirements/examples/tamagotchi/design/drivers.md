# Architecture Drivers

## Architecturally Significant Requirements
- FR-001: high_impact_function (significance: Makes durable state a first-class element of the system rather than an in-memory detail: the pet's authoritative value lives on disk between process lifetimes, so a persistence element must own the on-disk representation and the last-saved timestamp that every later computation is anchored to. Nothing else in the system can be the source of truth across a restart.)
- FR-002: high_impact_function (significance: Time advances while the process does not exist, so state cannot be maintained by an in-session tick loop. This forces decay to be a pure function of (saved state, elapsed interval) evaluated at load, separating a stateless computation element from both the storage element that supplies the saved value and the clock source that supplies the interval. It is the requirement that makes this a resumable simulation rather than a game loop.)
- FR-008: high_impact_function (significance: Introduces a terminal, irreversible state that continuous stat arithmetic cannot express — death is permanent per the Q-2 resolution, so no stat increase may revive the pet. That asymmetry forces a lifecycle element with explicit transitions and threshold timers, sitting above the stat engine and gating every care action, rather than a threshold check scattered through the interactions.)
- FR-009: high_impact_function (significance: The only requirement that crosses the process boundary outward. It is the sole reason an external element (the OS notification service) appears in the architecture at all, and it forces an adapter seam so the one platform-specific egress path is isolated and can be absent on platforms staged after v1 without touching the core.)
- NFR-001: quality_attribute (significance: A +/- 1 unit tolerance over intervals spanning five orders of magnitude is only testable if the computation is deterministic and reachable without a real clock or real elapsed time. This forces the clock to be an injected dependency rather than an ambient call, which is what makes the decay computation a separately verifiable element instead of a launch-path side effect.)
- NFR-002: quality_attribute (significance: A <=1% idle CPU budget rules out any continuously running animation or polling loop, so the idle system must be event- and timer-driven with the UI quiescent (and cheap or absent) when unfocused. The 150 MB resident ceiling additionally bounds how much may be held in memory, which is what keeps the pet state small and single-file rather than an in-process store.)
- NFR-003: quality_attribute (significance: Requiring every mood to be perceivable without color and announceable by name means mood must exist as a named semantic value in the model, derived from stats by a rule, before anything is drawn. That splits mood derivation from mood rendering — the presentation element consumes a mood token it did not compute, and the accessible name and the sprite are two renderings of one value.)
- NFR-004: quality_attribute (significance: Tolerating a kill at any point during a write means no caller may write the state file directly. The commit protocol (temp file, fsync, rename) and the load-side integrity check must be owned by a single element that exposes only a transactional save, so that the number of code paths that can leave a half-written file on disk is exactly zero.)
- NFR-005: quality_attribute (significance: Zero outbound connections under default settings is a property of the whole dependency graph, not of one element: it means no component, and no dependency a component pulls in, may hold a network client. It removes update, telemetry, and crash-reporting elements from the design space entirely and makes the local log the only diagnostic channel.)
- NFR-006: quality_attribute (significance: One codebase across three OS families with no feature loss forces every OS-specific capability — app-data path resolution, atomic rename semantics, notification delivery, accessibility tree — behind a narrow platform port. The core simulation must depend on those ports and never on an OS API directly, so adding macOS and Linux after v1 changes adapters only.)
- NFR-007: quality_attribute (significance: Requiring a durable record of every decay computation and lifecycle transition means those elements must emit observable events rather than mutate state silently, and adds a local log sink element that would not otherwise exist. Combined with NFR-005 it fixes the diagnostic architecture: append-only, on-device, user-readable, with no remote counterpart.)
- CON-001: constraint (significance: Eliminates whole runtime families (a bundled browser engine) from the design space before decomposition begins, which is what fixes the top-level topology as a native core process plus an OS-supplied webview. The core/UI split is therefore a process boundary imposed by this constraint, not a stylistic layering choice, and simulation logic must sit on the native side of it.)
- CON-002: constraint (significance: Fixes the system boundary: there are no remote systems, so every external element in the architecture is an OS service and every interface is in-process or OS-local. It also forecloses the usual escape hatches — no server-side balance tuning, no remote config, no cloud save — so anything the design would otherwise defer to a service must be solved locally.)

## Tradeoffs
- IF-002 accepts diagnostic entries asynchronously and makes durability an explicit, separate `flush` rather than writing synchronously on the decay path. Gains: No disk write inside the stat-mutation or decay path, which fires on a timer for the life of the process — the single largest recurring charge against NFR-002's <=1% idle CPU budget. Costs: Every entry between acceptance and flush is lost to an abrupt exit, and that is exactly the set NFR-007's '24-hour session has 0 missing transition entries' measures. The interface's own second error mode names this as the price. Affected: NFR-002, NFR-007.
- IF-003 commits synchronously on every stat change rather than accepting the write and settling it later. Gains: No queued write can be in flight at kill time, which is the precise window NFR-004's 200 randomized fault-injection trials are designed to find. Costs: Disk latency inside every care action and every in-session decay tick, charged against NFR-002's idle budget and against the responsiveness of FR-003 to FR-006. Affected: NFR-004, NFR-002, FR-001.
- IF-006 is recorded as synchronous, resolving in favour of CMP-003's blocking death-gate read over CMP-005's and CMP-006's need for a push. Gains: No care action can run against a stale terminal flag — 'a missed gate revives a dead pet' — which is what makes FR-008's terminal state actually terminal under Q-2. Costs: Half the contract is misdescribed by its own declared interaction, and the two push consumers get a notification stream the field denies. Mood and window updates can lag a transition, which FR-007's one-second bound has to absorb. Affected: FR-008, BR-001, FR-007, NFR-002.
- CMP-001 contains platform-specific behaviour (app-data path resolution, atomic rename semantics) inside the component rather than exposing it as a platform port. Gains: Exactly one component changes per OS and the simulation never touches an OS API directly, which is the letter of what CON-003 and NFR-006 ask of the core. Costs: The two OS-specific behaviours most likely to differ (and most likely to break NFR-004's atomicity guarantee on a filesystem that renames differently) are neither substitutable nor testable in isolation, which is the structure NFR-006's significance explicitly demands. Affected: NFR-006, CON-003, NFR-004.
- The architecture has no network surface at all — no telemetry component, no consent record, no remote-config path. Gains: NFR-005's '0 outbound connections' and CON-002's 'networking disabled at the OS level' measures hold by construction rather than by discipline; there is no code path to audit. Costs: NFR-005's own opt-in clause ('unless the owner grants explicit opt-in consent', 'telemetry endpoints are contacted only after an explicit opt-in flag is set') has no seam to grow into. And with no remote config, Q-1's decay-curve tuning can only ever reach an owner as a full client update. Affected: NFR-005, CON-002, NFR-007.
- IF-007 pulls the Mood on edges CMP-006 already observes, instead of pushing a mood-changed notification. Gains: One derived value with one timing. A third independently-timed stream could deliver a Mood that disagrees with the stat values drawn beside it, which under NFR-003 would mean the announced accessible name and the rendered sprite disagreeing. Costs: One extra synchronous call per observed change, and FR-007's one-second threshold-crossing budget now depends on CMP-006 re-deriving promptly on every edge rather than on the mood source deciding when to speak. Affected: NFR-003, FR-007.
- One shared webview surface (CMP-006) rather than a native view per platform. Gains: NFR-006's 'single codebase, no platform-specific feature loss' with a solo or small team and no platform specialists. Costs: NFR-003's accessibility now rests on the webview's accessibility tree across three OS families, with no port isolating it, and CON-001's footprint rests on whatever engine the OS supplies. Affected: NFR-006, NFR-003, CON-001.
- Q-4 resolved to Tauri — a Rust core with an OS-supplied system webview — over Electron and a native view per platform. Gains: The runtime's own idle baseline fits inside NFR-002's <=1% CPU and <=150 MB budget with headroom left for the pet's state, where a bundled Chromium shell spends most of that budget before the application has done anything; CON-001's footprint boundary is met by the technology choice rather than tuned for afterwards, which is exactly what that constraint asks. Costs: The UI now runs on whatever webview engine each OS supplies, so rendering and accessibility behaviour vary by platform and by OS version and are not pinned by the build — the same price the shared-webview tradeoff above pays, now fixed by the runtime rather than by the UI decomposition. Affected: NFR-002, CON-001.
- Q-3 resolved to Windows first for v1, with macOS and Linux staged after it. Gains: One set of app-data path rules, rename semantics, notification service and accessibility tree to get right for v1, which is what makes NFR-002's and NFR-004's measured budgets provable on a real reference machine instead of asserted across three OS families at once. Costs: CON-003 is only partially satisfied in v1 — no build is produced for each of the three targets at ship time — so every platform-touching surface must stay narrow and port-shaped to keep the staged platforms cheap, and nothing verifies that discipline until the second platform is actually attempted. Affected: CON-003.
- Q-2 resolved to permanent death: one terminal lifecycle path, no reset setting. Gains: FR-008's terminal state is genuinely terminal, so the lifecycle element gates every care action on a single irreversible transition rather than arbitrating between a dead state and a revival path, and the stakes BR-001 exists to create are real ones. Costs: BR-001's statement still asserts that 'upon death the pet is reset to a new pet according to the death-handling policy' and now contradicts the design, so the requirement needs amending upstream (Q-5); and an owner who loses a long-lived pet has no in-app recovery at all, which is the deliberate price of the stakes. Affected: FR-008, BR-001.

## Sensitivity Points
- The arity of IF-004's `apply_decay` — whether the decay model is a function of (stats, elapsed_interval) alone — affected: FR-002, NFR-001, BR-002. IF-004's own body states it: 'If Q-1 resolves to a curve that depends on more than elapsed time — a neglect streak, or a per-Stat schedule that varies with lifecycle state — this contract grows an input and both consumers change with it.' Q-1 is the only still_open question, and the single most load-bearing contract in the set is the one it can reshape. CMP-002, CMP-003 and CMP-007 all move with it. Nothing else in the design is one unanswered question away from a signature change.
- Where IF-002's `flush` sits relative to process exit — affected: NFR-007, NFR-002. NFR-007 permits zero missing transition entries in 24 hours, and the entire margin is the accept-to-flush window. Move the shutdown flush one step later in CMP-007's sequence, or lose it on an abrupt exit, and NFR-007 fails with no other change to the design. Tipping it the other way — synchronous recording — puts a disk write inside every stat mutation and moves the failure to NFR-002.
- The in-session decay tick interval, which is simultaneously a Q-1 tuning value and the commit frequency — affected: NFR-002, NFR-004, FR-001. FR-001 commits on every stat change and IF-003 commits synchronously, so the tick rate chosen for decay fidelity is also the disk-write rate charged to NFR-002's <=1% idle budget. IF-003's body already names the escape ('coalescing commits, not ... making them asynchronous') but coalescing reopens NFR-004's in-flight-write window. One untuned number decides whether NFR-002 and NFR-004 can both hold.
- Whether the lifecycle death gate stays in CMP-004 behind IF-006 or is cached in CMP-003 — affected: FR-008, BR-001. IF-006's body names this as what would flip its interaction to asynchronous. Caching the terminal flag in CMP-003 buys the push the other two consumers want, at the cost of two components holding the same terminal flag with a window in which they disagree — and that window is precisely the one in which a care action revives a dead pet. A change made for a presentation reason would silently move a correctness boundary.
- Whether NFR-006's platform port is one seam or four — affected: NFR-006, CON-003, NFR-003. Only notification delivery has a port today. If app-data path resolution, atomic rename semantics and the accessibility tree do not grow ports before the second platform ships, NFR-006's measure ('the suite passes on a supported version of each OS; 0 platform-exclusive features') is met by editing CMP-001 and CMP-006 internals instead of substituting adapters — which is the failure mode the ASR exists to prevent, arriving as maintenance cost rather than as a test failure.
- The IPC latency asymmetry on IF-005's notification path to CMP-006 — affected: FR-007, NFR-002, CON-001. IF-005's body concedes that CMP-006 receives stat notifications over an IPC hop the in-process consumers do not pay, and FR-007's one-second threshold-crossing budget must absorb it — while IF-007's pull adds a second hop on the same edge. IF-005's second error mode also permits notifications to be coalesced or dropped under load; a coalesced notification that spans a mood-band boundary makes FR-007's 'verified for every band boundary' measure unprovable. Nothing in the set budgets the hop.
